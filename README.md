# JoyShop — Professional Flask + SQLite Shop

JoyShop is a responsive fashion and lifestyle shop built with Python Flask and SQLite. It includes separate customer and administrator dashboards.

## Features

### Customer
- Create an account and log in
- Browse bags, shoes, clothing, and accessories
- Search and filter products
- Add products to a session-based cart
- Checkout and create an order
- View order history and order status

### Admin
- Overview dashboard with sales, product, order, and customer counts
- Add, edit, and hide products
- View customer orders
- Update order status (Processing, Shipped, Completed, Cancelled)
- View registered customers

## Run locally

Use Python 3.10+.

```bash
python -m venv .venv
```

Windows:
```bash
.venv\Scripts\activate
```

macOS/Linux:
```bash
source .venv/bin/activate
```

Install dependencies and run:
```bash
pip install -r requirements.txt
python app.py
```

Open http://127.0.0.1:5000

On first run, the app creates `joyshop.db` and sample products.

### Default admin for local testing
- Email: `admin@joyshop.com`
- Password: `admin123`

Change the admin credentials before deployment using environment variables:
- `ADMIN_EMAIL`
- `ADMIN_PASSWORD`

The default admin is created only when that email does not already exist in the database. If you change these environment variables after the first database initialization, the existing admin account is not automatically changed.

## Deploy to Render

1. Upload this project to a GitHub repository.
2. In Render, choose **New + → Blueprint** and connect the repository.
3. Render reads `render.yaml` and creates the web service and persistent disk.
4. Set the `ADMIN_PASSWORD` value when Render asks for it.
5. Deploy. Open the generated `onrender.com` URL.

The included Render blueprint uses a paid Starter web service because SQLite needs persistent storage. The disk is mounted at `/var/data`; the database is stored at `/var/data/joyshop.db` and survives normal redeploys/restarts.

If you use a free Render web service without a persistent disk, local SQLite data can be lost when the service restarts, redeploys, or is replaced. Do not use that setup for a live shop that must retain accounts and orders.

## Important security and production notes

- Passwords are stored as Werkzeug password hashes, not plain text.
- Forms use CSRF protection.
- The Flask secret key is generated by Render through `SECRET_KEY`.
- The starter admin credentials are for testing only. Set a strong unique `ADMIN_PASSWORD` before deploying.
- This is a small starter shop. It does not yet include payment processing, shipping integration, email verification, password reset, image uploads, tax/shipping calculations, or production-grade inventory locking for high traffic.
- Do not collect card details directly. Integrate a trusted payment provider if you add online payments.
- SQLite is a real database, but for a high-traffic multi-user shop, use managed PostgreSQL instead.
